# Qwen3-4B-Base → existing 124.4M student: first pilot

[PR #31](https://github.com/koogle/lm-exploration/pull/31) adds the experiment.
[Completed Modal run](https://modal.com/apps/radiantai/main/ap-nX9BofrKgiejSo93utVmGA).
Exact counters and settings are in [the JSON report](qwen4b-byte-pilot-20261021-02.json).

- 261,907 student loss tokens, 1,133 optimizer updates; stopped before the next
  window would exceed 262,144. 224,675 shared boundaries (85.8% of loss tokens)
  received byte-marginal supervision. 16 windows skipped for Unicode/normalization
  or empty-prefix reasons; these are not counted as trained tokens.
- One L40S; 153.07 seconds for training including checkpoint commits; 171.51
  seconds total worker time. Image building and initial teacher download are
  outside this warm-cache worker timing. 1,711 accepted tokens/sec.
- Peak allocated CUDA memory: 10,631,648,256 bytes. This is not peak reserved
  memory or the full GPU process footprint.
- Code validation CE **1.27244 → 1.37822**, a worsening of 0.10578 nats/token
  (~8.3%). Only 16 fixed windows / 3,724 tokens: no capability claim and no
  statistically representative estimate. No matched CE-only control yet.
- Final checkpoint on `lm-exploration-distillation`:
  `qwen4b-byte-pilot-20261021-02/step-000001133.pt`.
  Full source, request, snapshot manifest, metrics and parent digest are retained
  in the run directory. Use the archived source for exact resume: later additions
  to this experimental package change its strict source identity.

The first attempt ([Modal](https://modal.com/apps/radiantai/main/ap-DsiIsH4u2hmnMXLJEXnqy4))
failed before optimization because Qwen's tokenizer declares Unicode normalization.
The successful attempt permits the tokenizer but skips any window that normalization
would change; reconstructed teacher/student bytes must still agree exactly.

**Do not infer that 5B has started or completed.** Linear projection is about
811.8 L40S-hours for 5B accepted tokens, before extra operational overhead. This
pilot provides no evidence that the current recipe is worth that scale. Next
experiments should compare a matched CE-only control, lower LR/teacher weight,
larger effective batch and representative coding evaluation. Batching is also
needed to make teacher inference efficient. The candidate fits comfortably; the
objective and recipe still need qualification.

The vLLM qualification uses the durable step-1,000 checkpoint from this same run,
not the final step-1,133 checkpoint. Its results are recorded separately.

## vLLM qualification completed

[Actual L4 run](https://modal.com/apps/radiantai/main/ap-foxF6U9MgcL6LVCAMqTYfR)
passed on the step-1,000 checkpoint with vLLM 0.11.0, FP32 and the native
Llama backend. All five code prompts matched the reference greedy token;
maximum next-token log-probability error was **1.1593e-5**. Native-to-HF
export maximum absolute logit error was **2.5511e-5** on its probe.
[Machine-readable report](vllm-parity-20261021.json).

The export is on the distillation volume at
`qwen4b-byte-pilot-20261021-02/step-000001000-hf`. No always-on serving endpoint
was deployed. This is numerical serving compatibility, not a coding benchmark;
longer generations, BF16 and the complete evaluation harness need broader checks.
